# api

The FastAPI service. It is one service and handles auth, projects, intake,
estimates, admin, approvals, and agent streaming.

- All routes live under `/api`. Write endpoints accept an `Idempotency-Key` header.
- Database access goes through a repository layer that applies `partner_id`.
- Runs on ECS Fargate. Python is managed with `uv`; run everything through Docker
  Compose (see `.kiro/steering/docker.md`).

New routes, repositories, and services belong here.

## Database and migrations

Schema lives in `app/data/models/` (19 tables, UUID keys, `partner_id` on every
tenant table). Models and session execution stay inside `app/data/`; the
tenant-access lint guard (foundation task 8) enforces that.

Migrations are Alembic, run as a **one-off task** before the service rolls (locally
the `migrate` Compose service; in AWS a one-off ECS task). The URL comes from
`DATABASE_URL`.

```
docker compose run --rm migrate                      # alembic upgrade head
docker compose run --rm migrate alembic current
docker compose run --rm migrate alembic downgrade base
docker compose run --rm migrate alembic revision --autogenerate -m "message"
```

Autogenerated revisions are a starting point: review them, and add triggers or
other DDL by hand. Migrations stay data-free (the first `platform_operator` is
created by a separate bootstrap task).

Migration and schema tests need Postgres (`docker compose up -d --wait db`, or run
without `--no-deps`). They create and drop a throwaway database per test.

Immutability: `project_versions`, `estimates`, `architecture_graphs` and the
append-only `audit_events`, `plan_approvals`, `artifacts`, `validation_runs` reject
UPDATE, DELETE and TRUNCATE in the database. `template_versions` content is
immutable and only `status` may advance (draft, published, retired).
`deployment_plans` identity and hash fields are fixed; only `status` may change.
