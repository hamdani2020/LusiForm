# Fixture default

Terraform project for Example Customer, generated by Lusiform from the startup
reference architecture, template version 1.0.0, for the
us-east-1 region.

Review this project before you deploy it. It describes the infrastructure below and
nothing else; it does not certify anything about the application or the account it
runs in.

## What it creates

A single-region footprint in one VPC:

- **Network:** public, private application, and isolated data subnets in two
  Availability Zones, an internet gateway, NAT gateways for the active zones, and VPC
  flow logs.
- **Compute:** an ECS Fargate service behind a public Application Load Balancer, with
  CPU-based auto scaling.
- **Database:** Amazon RDS for PostgreSQL 16 in the isolated data subnets, encrypted
  with a customer-managed key. The master password is created and held by RDS in
  Secrets Manager; it is not in these files.
- **Monitoring:** KMS-encrypted CloudWatch log groups and alarms for load balancer 5xx
  responses, ECS CPU, database CPU, and database free storage. The alarms notify
  nobody until you attach an SNS topic or other action.
- **IAM:** least-privilege roles for the ECS tasks, VPC flow logs, and RDS enhanced
  monitoring.

## Parameters

| Parameter | Value |
| --- | --- |
| Availability Zones running the workload (`az_count`) | 2 |
| Task size (`task_size`) | 0.25vcpu-0.5gb |
| Minimum tasks (`min_tasks`) | 2 |
| Maximum tasks (`max_tasks`) | 6 |
| Database instance class (`instance_class`) | db.t4g.micro |
| Database storage in GB (`storage_gb`) | 20 |
| Backup retention in days (`backup_retention_days`) | 7 |
| Log retention in days (`log_retention_days`) | 30 |

These are the defaults in `variables.tf` and the values in `terraform.tfvars.example`.
Changing them here does not change the Lusiform project; generate a new version in
Lusiform instead, so the diagram and cost estimate stay in step.

## Requirements

- Terraform >= 1.10.0.
- AWS credentials for the account you are deploying to, with permission to create the
  resources above.
- An S3 bucket for Terraform state in that account.
- A container image that listens on the container port (default 8080) and answers the
  health check path (default `/`) with a 2xx or 3xx response.

## Deploy

Copy the example variables and set at least `container_image`:

```
cp terraform.tfvars.example terraform.tfvars
```

Initialize with your state bucket. Locking uses a lock file in the same bucket, so no
DynamoDB table is needed:

```
terraform init \
  -backend-config="bucket=<state-bucket>" \
  -backend-config="key=<state-key>" \
  -backend-config="region=<state-bucket-region>"
```

Review the plan, then apply it:

```
terraform plan -out=tfplan
terraform apply tfplan
```

Terraform prints the load balancer address as `alb_dns_name`.

## Application settings

The container receives these environment variables:

- `DB_HOST`, `DB_PORT`, and `DB_NAME` for the database connection.
- `DB_CREDENTIALS`, the database credentials as JSON, injected from Secrets Manager by
  ECS. The secret is created by RDS; its ARN is the `database_secret_arn` output.

The load balancer serves HTTP unless you set `certificate_arn` to an ACM certificate in
the same region, in which case it serves HTTPS and redirects HTTP to it. Point your own
DNS name at `alb_dns_name`.

## Destroying

The database and load balancer have deletion protection on, and the database takes a
final snapshot when it is destroyed. To tear the project down, first set
`deletion_protection = false` (and `skip_final_snapshot = true` if you do not want the
snapshot), run `terraform apply`, and then `terraform destroy`.
